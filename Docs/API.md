Err:`{"ok":false,"code":C,"message":M}`. Writes: inspect first, mutate small, compile/validate, save only if acceptable. Asset path accepts `/Game/P/A` or `/Game/P/A.A`. `exclude_paths` aliases:`excluded_paths`,`exclude_path_prefixes`,`excluded_path_prefixes`; value array or comma string; prefix match before loading. Set flags true/false to trade tokens for exact node/pin/link/type detail. Pin type input categories:`bool|byte|int|int64|float|double|real|string|name|text|object|class|vector|rotator|transform|struct`; optional `container=none|array|set|map`,`is_reference`,`is_const`; `object/class` need `class_path`; `struct` needs `struct_path`.

## Node placement policy

**Prefer manual node placement.** Inspect authored positions, choose explicit execution/branch/cancellation/data lanes, then use `set_property` with the asset path, `object_path="<asset>.<name>:<graph>.<node>"`, `property="NodePosX"` or `"NodePosY"`, and the manually chosen coordinate as `value`. Reinspect coordinates, compile and save. Only coordinates on nodes belonging to the supplied Blueprint bypass the editable-property check.

**Automatic tidy is deprecated.** `format_blueprint_graph` and both automatic strategies produce layouts that are unreadable for humans. They are guarded against accidental use, advertised as deprecated in MCP descriptions/metadata and REST guidance, and retained only behind an explicit legacy opt-in. Do not run them after manually arranging nodes.

## Animation

Raw animation data is owned by `IAnimationDataModel`; every write goes through `IAnimationDataController` inside a transaction bracket, never through `UAnimSequence` fields. Writes are limited to `/Game` assets and leave the sequence dirty unless `save=true` (or call `save_asset`). Changing keys triggers recompression, so batch edits into one call. `bone` defaults to the skeleton's root bone (ref-skeleton index 0). Frame indices are key indices in `0..number_of_keys-1`. Animation errors include `load_failed,unsupported_animation_asset,bone_track_not_found,invalid_arguments,write_failed`.

`inspect_anim_sequence({asset_path,bone?})->asset_path,name,skeleton,play_length,number_of_frames,number_of_keys,frame_rate,enable_root_motion,force_root_lock,root_motion_root_lock,bone_track_count,root_bone,has_root_track`.

`get_root_motion_track({asset_path,bone?,start_frame=0,end_frame=last,max_keys=512})->asset_path,bone,number_of_keys,start_frame,end_frame,stride,keys[{frame,time,x,y,z,pitch,yaw,roll}]`; results are decimated with `stride` when the range exceeds `max_keys`.

`set_root_motion_keys({asset_path,bone?,keys:[{frame,x?,y?,z?,pitch?,yaw?,roll?}],save=false})->asset_path,bone,number_of_keys,applied_keys,dirty,saved?`; per-key partial update, unlisted channels keep their current value, so Z can be moved on its own. Rejects a `frame` outside the sequence range.

`list_skeleton_bones({asset_path,query?})->asset_path,skeleton,bone_count,returned,bones[{index,name,parent,has_track}]`; `query` is a substring filter on the bone name.

`get_bone_component_transform({asset_path,bone?|bones:[names],start_frame=0,end_frame=last,max_keys=256})->asset_path,space="component",number_of_keys,start_frame,end_frame,stride,keys[{frame,time,bones{name:{x,y,z,pitch,yaw,roll}}}]`; composes each bone up the reference-skeleton parent chain, so translations are relative to the mesh component origin rather than the parent bone. Bones without a track fall back to the ref pose. Use to compare two sequences in the same space - e.g. where a weapon hand is at the contact frame versus where the target's chest is.

`flatten_root_motion_axis({asset_path,bone?,axis="z",value=0,start_frame=0,end_frame=last,blend_frames=0,save=false})->asset_path,bone,axis,value,touched_keys,dirty,saved?`; drives one translation channel to `value` over the range, easing in across `blend_frames` so the flattened tail does not pop. Use for an animation that ends off the ground: `{axis:"z",value:0,blend_frames:N}`.

### Anim notifies

Works on any `UAnimSequenceBase` (AnimSequence, AnimMontage, AnimComposite). Times are seconds on the asset's own timeline; for a montage that is the montage time, not the source sequence time. Writes are limited to `/Game` assets, run inside one undo transaction, and leave the asset dirty unless `save=true`. The notify object is built and its `properties` are validated before the asset is touched, so a bad value fails the whole call. Errors include `load_failed,class_not_found,anchor_not_found,confirmation_required,invalid_arguments`.

`inspect_anim_notifies({asset_path,class_filter?,include_properties=true})->asset_path,asset_class,play_length,frame_rate?,tracks[{index,name}],sections?[{name,start_time}],notify_count,notifies[{index,kind,name,class,time,frame?,duration?,end_time?,track_index,track,trigger_chance,properties?{}}]`; `kind` is `notify`, `state` or `named` (skeleton notify). `class_filter` matches the notify class name, the name without `_C`, or a path substring. `properties` lists the editable properties the notify class adds, as exported text. `index` is what `remove_anim_notify` takes.

`add_anim_notify({asset_path,notify_class,time?,frame?,anchor?{class,edge="begin",offset=0},duration?,track?,create_track=true,properties?{},trigger_chance=1.0,skip_duplicates=true,save=false})->asset_path,added[notify],skipped[{time,reason}],notify_count,dirty,saved?`; pass exactly one of `time`, `frame` or `anchor`. `notify_class` is a class path such as `/Script/Project_S.SoundFeedbackAnimNotify` or a Blueprint notify `/Game/.../ANS_X.ANS_X_C`. `anchor` places one notify per existing notify whose class matches `anchor.class`, at its `begin` or `end` edge plus `offset` seconds, clamped into the animation. A notify state needs `duration`. `track` defaults to the first track and is created when missing. `properties` values are property text; a gameplay tag property also takes a bare tag name and rejects an unregistered tag. `skip_duplicates` skips a placement that already has the same class, time and property values, so re-running a call is harmless. Example: `{asset_path:"/Game/.../AM_Torch_Attack01",notify_class:"/Script/Project_S.SoundFeedbackAnimNotify",anchor:{class:"ANS_Mob_AttackCollision",edge:"begin",offset:-0.05},properties:{soundTag:"Sound.Combat.Swing"}}`.

`remove_anim_notify({asset_path,index?,indices?:[int],class?,time?,confirm,save=false})->asset_path,removed[notify],notify_count,dirty,saved?`; destructive and requires `confirm=true`. Pass one of `index`, `indices` (both from `inspect_anim_notifies`) or `class` (optionally narrowed to one `time`).

## Retargeting

IK Retargeter errors include `invalid_arguments,load_failed,create_failed,align_failed`. Every write goes through `UIKRetargeterController`, never the asset's fields: the controller keeps the retarget pose sorted hierarchically and reinitializes any running processor, and a direct write skips both. A retarget pose stores one **bone-space** delta per bone, applied as `GlobalRetargetPoseRotation = GlobalRefRotation * Delta` - so a delta measured as "target bone orientation relative to the source bone orientation" (`conj(q_source) * q_target`, constant across frames when the only error is pose misalignment) is written back inverted, with no change of basis. Measure that residual with `get_bone_component_transform` on a source/retargeted pair, correct, then measure again; alignment is an iterative loop, not one shot, because a parent's delta moves its children.

`inspect_ik_retargeter({asset_path})->asset_path,source{ik_rig,preview_mesh,current_retarget_pose,retarget_poses[],bone_rotation_offsets[{bone,pitch,yaw,roll,angle}],bone_rotation_offset_count,root_translation_offset{x,y,z}},target{...},chain_mapping[{target_chain,source_chain,mapped}],chain_count`. Reads a retargeter without changing it. Only bones whose stored delta exceeds 0.001 degrees are listed, so an unedited pose reports an empty array rather than the whole skeleton as identity.

`create_retarget_pose({asset_path,name,source_or_target="target",duplicate_from?,set_current=true,save=false})->asset_path,pose,source_or_target,current_retarget_pose,dirty,saved?`. `duplicate_from` copies an existing pose instead of starting from the reference pose. Make a new pose before aligning rather than editing the one in use: it keeps the old result intact for an A/B and for a one-field rollback.

`set_retarget_pose_bone_rotation({asset_path,bone,rotation{pitch,yaw,roll}|{x,y,z,w},source_or_target="target",mode="set"|"compose",save=false})->asset_path,bone,source_or_target,pose,mode,previous_offset,offset,dirty,saved?`. Writes one bone's delta in the current retarget pose. `set` replaces the stored delta; `compose` post-multiplies onto it, which is what an iterative correction pass wants because each pass only measures the residual the previous one left.

`auto_align_retarget_pose({asset_path,source_or_target="target",method="chain_to_chain",bones?[names],save=false})->asset_path,source_or_target,pose,requested_bone_count,bone_rotation_offset_count,largest_offset_degrees,largest_offset_bone,dirty,saved?`. This is the editor's Auto-Align. Methods: `chain_to_chain` (uses the mapped retarget chains - the usual choice), `mesh_to_mesh` (skinned geometry direction, for leaf bones with no chain tangent), `local_rotation_axes`/`global_rotation_axes` (only correct when both skeletons share axis conventions). **Omitting `bones` resets the entire pose first**, so a full align discards manual corrections; pass `bones` to align a subset without touching the rest. Both preview meshes must be set on the retargeter or the call fails with `align_failed`, because alignment resolves the asset onto real skeletons.

`reset_retarget_pose({asset_path,pose?,bones?[names],source_or_target="target",save=false})->asset_path,pose,source_or_target,reset_bone_count,dirty,saved?`; empty `bones` resets every bone in the pose. `pose` defaults to the current one.

`retarget_animations({retargeter,animations:[paths],destination_path?,prefix?,suffix?,search?,replace?,source_mesh?,target_mesh?,include_referenced=false,overwrite=false,export_only_animated_bones=true})->retargeter,source_mesh,target_mesh,destination_path,requested,created[],created_count,overwrite,missing_animations?`. Batch duplicate-and-retarget, the same operation as the editor's "Retarget Animation Assets" dialog. Meshes default to the retargeter's preview meshes. `include_referenced` is off by default here: a flat list of sequences would otherwise drag in the montages and blendspaces that reference them. `overwrite=true` replaces existing files in place instead of appending a numeric suffix - which is what re-exporting a set after fixing the retarget pose wants, and which **discards notifies, curves and sync markers authored on the previous results**.

## Niagara

Niagara errors include `invalid_arguments,load_failed,not_found,ambiguous,unsupported_emitter,add_failed,asset_editor_open`. **Every write tool refuses a system that is open in the Niagara editor** and returns `asset_editor_open`. An open asset editor owns a view model caching the emitter handles and the stack built from them; a structural change behind it leaves that cache dangling and the next thing the editor touches crashes it outright, while a rapid iteration write is neither shown nor kept - saving from that window overwrites it. Close the window, then write. Two different stores are writable and they are not interchangeable. **User parameters** live on the system (`User.X`) and are what a spawning component can override per instance. **Module inputs** left as plain literals live in each script's rapid iteration store as `Constants.<Emitter>.<Module>.<Input>`; writing one is what typing a number into a module input in the stack UI does, and it needs no recompile. An input driven by a dynamic input or a curve is in neither store and is reported as not found rather than guessed at. Emitter removal is not offered: it also has to rebuild the system graphs through an unexported NiagaraEditor helper, so disable the emitter instead.

`inspect_niagara_system({asset_path,emitter?,query?,include_constants=true,limit=200})->asset_path,emitter_count,emitters[{index,name,enabled,local_space,determinism,renderers[],stateless?}],user_parameters[{name,type,value}],constants[{emitter,script,name,type,value}],constants_truncated`. `query` is a substring filter applied to both parameter lists; `emitter` narrows to one emitter and accepts `System` for the system scripts. `renderers` names the renderer class per emitter, which is how you tell a ribbon core jet from a sprite splash.

`set_niagara_user_parameter({asset_path,parameter,value,save=false})->asset_path,parameter,type,previous_value,value,saved?`. `parameter` takes `Velocity` or `User.Velocity`. `value` accepts a number, `[x,y,z]`, `{x,y,z}`/`{r,g,b,a}`, or a vector spelled as a string (`X=0,Y=0,Z=1`, `0 0 1`, `[0,0,1]`) - MCP clients serialise an untyped value as a string, so the string form is what a multi-channel write usually arrives as. A bare number fills every channel, and a colour or quat may omit its last component. Writable types: float, int, bool, vec2/3/4, position, color, quat.

`set_niagara_module_input({asset_path,emitter,parameter,value,compile=false,save=false})->asset_path,emitter,scripts[],parameter,type,previous_value,value,compiled?,saved?`. `emitter` is an emitter name or `System`. `parameter` takes the full `Constants.<Emitter>.<Module>.<Input>` name or any trailing part of it, e.g. `AddVelocityInCone.Cone Axis`; a partial name matching more than one parameter name is rejected with the candidates rather than resolved arbitrarily. One name can live in several scripts - a module in both the particle spawn and particle update stacks keeps a copy in each, and interpolated spawn replays update logic - so every copy is written and `scripts` reports which ones. `value` follows the same rules as `set_niagara_user_parameter`.

`add_niagara_emitter({asset_path,source_asset_path,new_name?,compile=true,save=false})->asset_path,source_asset_path,emitter,handle_id,emitter_count,compiled?,saved?`; copies the emitter rather than referencing it, so retuning the copy cannot reach back into the source asset. The name is made unique against the existing handles, and `new_name` renames it afterwards. Compiles by default because an emitter that was never compiled does nothing when the system plays. **`source_asset_path` must name a standalone NiagaraEmitter asset**; a NiagaraSystem is refused with `unsupported_source`. An emitter embedded in a system cannot be copied out of it - the copy keeps its inheritance, so `VersionedParent` in its `VersionData` still points at a private subobject of the source package, and SavePackage then rejects every later save of the destination with "Illegal reference to private object". The add itself appears to succeed, which makes that a worse failure than refusing up front. Copying an emitter between two systems is a clipboard operation in the editor UI and is not reachable from here.

`set_niagara_emitter_property({asset_path,emitter,enabled?,local_space?,compile=true,save=false})->asset_path,emitter,enabled,local_space,applied[],compiled?,saved?`; at least one of `enabled`/`local_space` is required. `local_space=false` is what keeps droplets and decals behind in world space when the emitting actor moves.

`compile_niagara_system({asset_path,force=false,save=false})->asset_path,compiled,force,saved?`; requests a compile and waits for it, so a save that follows writes compiled scripts rather than stale ones.

## Sequencer

`create_level_sequence({package_path,display_rate=30,tracks:[{spawnable,animation?,start_frame=0}],save=false})->asset_path,package,display_rate,tick_resolution,playback_end_tick,tracks[{spawnable,binding_id,animation?,start_frame?,play_length?}],dirty,saved?`. `/Game` only; rejects an existing package. `spawnable` takes a Blueprint asset path or a native class path and is added as a spawnable binding. `animation` adds a skeletal animation section on that binding; `start_frame` is in display frames and is converted to tick resolution for placement. Playback range is set to the longest track. Sequencer errors include `invalid_arguments,already_exists,load_failed,create_failed`.

`inspect_level_sequence({asset_path,at_frame?,include_keys=false,max_keys=128})->asset_path,name,display_rate,tick_resolution,playback_start,playback_end,at_frame?,bindings[{binding_id,name,kind,class?,parent_binding_id?,template_class?,template_transform?,tracks[{type,sections[{type,start_frame?,end_frame?,animation?,animation_length?,slot_name?,constraint_binding_id?,attach_socket?,attach_component?,channels[{name,type,key_count,value?,stride?,keys?}],evaluated_transform?}]}],transform_at_frame?,transform_source?}],root_tracks[]`. Reads a level sequence without changing it. Attach sections report the binding they follow and the socket (bone) and component they attach to; a component binding reports the binding it is parented to. Frames in and out are display frames, converted to tick resolution internally. `at_frame` evaluates every double and float channel at that frame and rebuilds a transform from a transform section, reporting it as `transform_at_frame` with `transform_source` of `transform_track`, `template` or `none`; only a section whose range contains the frame is evaluated. `template_transform` is the spawnable preview actor root relative transform, which is where a binding stands when no transform track drives it. `include_keys` dumps channel keys, decimated with `stride` past `max_keys`. Sequencer errors include `invalid_arguments,load_failed`.

`set_level_sequence_channel_keys({asset_path,binding,channel,keys:[{frame,value}],save=false})->asset_path,binding,channel,track_type,updated_keys,added_keys,key_count,dirty,saved?`. Writes float or double channel keys on one binding. `binding` is the binding name or id and `channel` the channel name, both as `inspect_level_sequence` reports them (e.g. `hand_r_CONTROL.Rotation.X` on a Control Rig track); the first matching channel on the binding is used. `frame` is a display frame. An existing key at that frame keeps its interpolation and only has its value replaced; a missing one is added. Auto tangents are rebuilt once after the writes, and the whole call is one undo step. `/Game` only. Sequencer errors include `invalid_arguments,load_failed,binding_not_found,channel_not_found,write_failed`.

`open_level_sequence({asset_path})->asset_path,opened`. Opens the sequence in Sequencer; a Control Rig section reports no channels until this has happened once in the editor session.

`bake_level_sequence_animation({asset_path,binding,package_path,skeleton?,save=false})->asset_path,sequence,binding,play_length,number_of_keys,frame_rate,has_data_model,dirty,saved?`. Bakes a skeletal mesh binding to a new AnimSequence through the engine's Sequencer export (transforms, morph targets, attribute and material curves, local space). Samples at the sequence display rate with no custom time range, matching the editor dialog defaults. Refuses a `package_path` that already exists, including an unpulled LFS pointer on disk, with `already_exists`. Errors also include `bake_failed,create_failed`. `skeleton` is required when the binding has no animation section, such as a Control Rig only binding. Open a Control Rig sequence with `open_level_sequence` first: without that, every other baked frame can come out in the reference pose. Check the result with `get_bone_component_transform`.

`set_level_sequence_animation({asset_path,binding,animation,create_section=false,save=false})->asset_path,animation,animation_length,previous_animations,section_count,dirty,saved?`. Points every skeletal animation section on the binding at `animation`, leaving section ranges unchanged. `create_section` adds a section at the playback start when the binding has none. One undo step.

`remove_level_sequence_track({asset_path,binding,track_type,save=false})->asset_path,track_type,removed_count,purged_count,dirty,saved?`. Removes every track of class `track_type` (as `inspect_level_sequence` reports it, e.g. `MovieSceneControlRigParameterTrack`) from the binding and moves it, plus any unlisted track of that class left in the package, out of the package so saves drop it. One undo step.

`copy_level_sequence_bindings({source_asset_path,target_asset_path,bindings:[],include_children=true,allow_unresolved=false,save=false})->source_asset_path,target_asset_path,copied[{binding_id,name,parent_binding_id?,custom_binding,reference_count,track_count,source_track_count}],unresolved[],dirty,saved?`. Copies bindings (names or ids as `inspect_level_sequence` reports them) from one level sequence into another with their GUIDs, spawnable custom bindings and preview actor templates, locators and every track, so attach sections keep their socket and the binding they follow. `include_children` also copies component bindings parented to a selected binding. Everything is validated before the first write: refuses a GUID the target already has (`already_exists`), a parent the target lacks (`parent_missing`), a legacy spawnable (`unsupported`), a template name already in the target movie scene (`name_collision`), and an attach section following a binding the target lacks (`unresolved_reference`, listing them, unless `allow_unresolved`). Target `/Game` only; one undo step.

## World and PIE

`spawn_level_actor({class,location?,yaw=0,label?})->object_path,label,location,dirty`. Places an actor in the open editor level; the level stays dirty until saved. One undo step.

`pie_control({action,path?})->action,running,queued,world?,time_seconds?`. `action` is start, stop, status, screenshot or save_level. `screenshot` writes the active viewport to the absolute `path` on the next rendered frame. `save_level` saves the open level on the next editor tick; use it for levels with landscape, because `save_asset` and `save_all_dirty` save inside the request and that asserts in the task graph when a landscape package is saved.

`pie_call_actor_function({actor,command})->actor,called`. Calls a function by name on a PIE actor found by name or label; `command` is the function name followed by its arguments.

`pie_get_actor_state({actor?,bones?:[]})->actor,location,yaw,time_seconds,bones?,view_target?,camera_location?`. Reads a PIE actor, or the player pawn when `actor` is omitted, with world space bone locations from its mesh.

`exec_console_command({command,world="auto"})->world,pie,handled[],output,truncated`. Runs console commands (CVars, `stat`, `Trace.Start`/`Trace.Stop`, `t.MaxFPS`) in the PIE world, the editor world, or PIE when running (`auto`). Separate several commands with `;`. Output is capped at 20000 characters.

`get_frame_stats({})->frame_ms,fps,game_thread_ms,render_thread_ms,rhi_thread_ms,gpu_ms,pie_world?,pie_time_seconds?`. Last frame timings as `stat unit` reports them; sample several times for a stable reading.

`read_log({lines=200,contains?})->path,total_lines,lines[]`. Tail of the editor log, optionally only lines containing `contains`.

`list_dirty_packages({})->content[],worlds[],count`. Unsaved content and level packages; check before restarting the editor.

`create_asset({asset_path,class,save=true})->object_path,class,factory,saved`. Creates an asset of any concrete class (for example `/Script/Niagara.NiagaraEffectType`) through its editor factory when one exists, otherwise as a plain object. Fails when the asset already exists.
