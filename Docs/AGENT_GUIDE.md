# LLMBlueprintBridge.AgentGuide.compact

Mode: structured editor code-mod API. Never raw-edit `.uasset`. Always inspect existing asset/state before mutation. Keep changes small enough that a failed compile maps to the last edit. Compile/validate after writes. Save only after acceptable result.

Global loop: `status` -> discover exact asset(s) -> focused inspect with minimum needed detail -> mutate one unit -> re-inspect exact ids/pins/properties -> connect/set defaults -> place nodes manually in readable execution/data lanes -> compile/validate -> save. For broad `/Game`: use `query/path/limit/exclude_paths`; confirm `skipped_excluded_count`.

Blueprint default inspect: start `inspect_blueprint({asset_path,include_nodes:false})`; request graph detail only when needed: `{include_nodes:true,graph:"EventGraph",include_pins:true,include_pin_types:false,include_pin_links:true}`; turn on types when creating/connecting ambiguous pins. Never guess node ids or pin names; use spawn/inspect returns. Prefer existing variables/functions/parent functions. Use `find_functions` before `spawn_node(call_function)`. Use `list_native_events`/`spawn_native_event` for engine events. Use `find_blueprint_actions`/`spawn_blueprint_action` for action-menu nodes; pass same `context_node/context_pin` used during search. Use `list_components` before component edits; mutate only `editable:true`. Use `get_class_defaults|get_property` before defaults; nested struct paths are valid. Use `duplicate_asset` before risky edits. Delete APIs require `confirm:true`; review references before `allow_referenced:true`.

Blueprint refactor: inspect source+dest -> create/rename destination function -> rebuild destination in small graph edits -> `find_function_references` old owner/function -> `retarget_function_call` each call -> compile every touched BP -> re-run references -> if zero, `delete_function_graph(confirm:true)` -> compile/save source,dest,touched callers.

Graph layout: **prefer manual node placements** after every node batch. Preserve useful authored positions, use explicit coordinates for changed nodes, separate branch/cancellation/exit lanes, and put data nodes beneath their consumers. `format_blueprint_graph` and **both** automatic strategies (`control_flow_parameters`, `dependency_layered`) are **DEPRECATED** because they produce unreadable placements for humans. Do not use them in normal work. The legacy tool rejects calls unless `allow_deprecated_automatic_layout=true`; that escape hatch is for an explicit request for legacy automation, not the default workflow.

For explicitly chosen manual layouts, inspect node object names/positions, then use `set_property({asset_path,object_path:"<asset>.<name>:<graph>.<node>",property:"NodePosX"|"NodePosY",value:<coordinate>})`. Only these coordinate fields bypass the editable-property check, and only when the node belongs to the supplied Blueprint. This preserves nodes, pins and links. Reinspect positions and save; do not run the automatic formatter afterward.

GAS loop: `list_gas_assets` scoped/excluded -> inspect nearby examples (`inspect_gameplay_ability/effect/attribute_set/tags`) -> `find_gameplay_tags` -> prefer `set_gameplay_tag_container,set_ability_tags,set_ability_policy,set_effect_duration,add/set/remove_effect_modifier,set_effect_stacking` over Blueprint graph gates -> graph task nodes only for behavior not expressible in GAS defaults -> `validate_gas_asset` -> `validate_gas_project` scoped -> compile/save. Built-in activation/cost/cooldown/tag fields beat manual branches: `ActivationRequiredTags,ActivationBlockedTags,SourceRequiredTags,SourceBlockedTags,TargetRequiredTags,TargetBlockedTags,CooldownGameplayEffectClass,CostGameplayEffectClass`. `generate_attribute_set_cpp` is guarded; use only if user explicitly asks for C++ generation.

StateTree debug loop: discover `list_statetree_assets` -> discover dependent BPs (`list_statetree_related_blueprints` or `find_blueprint_assets(derived_from=StateTreeTaskBlueprintBase|StateTreeConditionBlueprintBase|StateTreeEvaluatorBlueprintBase)`) -> `inspect_statetree` and retain state ids/paths -> `statetree_dependency_report` -> inspect important task/condition/evaluator BPs with `include_nodes:false` first -> `validate_statetree` or scoped project validation -> in PIE/SIE use `statetree_debug_status` then `statetree_debug_actor|snapshot` selector -> `statetree_compare_runtime_to_asset` -> `statetree_explain_blocked_transitions` before edits -> for time-varying bugs use trace start/read/stop -> duplicate important assets -> edit with full `state_id` or `state_path` -> `compile_or_validate_statetree` -> save. If runtime tools return `runtime_not_available`, continue with static inspection/validation/dependent BP inspection. Public APIs expose active frames/states/tasks/run status/event queue, not full private debugger condition packets; blocker explanations are high-confidence static+runtime guidance, not private trace dumps.

Common snippets: `find_functions({class_path:"/Script/Engine.KismetSystemLibrary",query:"print",limit:20})` then `spawn_node({asset_path,graph:"EventGraph",node_type:"call_function",class_path:"/Script/Engine.KismetSystemLibrary",function:"PrintString",x:300,y:0})`. `list_native_events({asset_path,query:"BeginPlay"})` then `spawn_native_event({asset_path,graph:"EventGraph",event_name:"BeginPlay"})`; if duplicate, reuse existing node. `find_blueprint_actions({asset_path,graph,query:"Sequence",limit:10})` then `spawn_blueprint_action({asset_path,graph,action_id,x,y})`. `set_class_default({asset_path,property:"PrimaryActorTick.bStartWithTickEnabled",value:true})`. `set_property({asset_path,target:"component",component:"Mesh",property:"Mobility",value:"Movable"})`.

Current scope: Blueprint creation, variables, function graphs, branch/call/variable/custom/native/action nodes, component/SCS editing, defaults/properties, pin defaults, pin connections, compile/save, asset lifecycle, Git asset/Blueprint revision diff, material graph inspection/editing, StateTree discovery/inspection/debug/edit/validate/recipes/reports/export, GAS inspection/config/validation/recipes. Not full coverage: every Blueprint node spawner, macro library action, component editor action, UMG tree, full MCP transport.
